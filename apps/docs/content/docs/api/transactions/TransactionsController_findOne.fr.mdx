## Aperçu

Obtenir une transaction par ID

Renvoie une transaction. Réponse 404 si elle n'existe pas ou n'est pas accessible avec cette clé API.


### Quand l'utiliser

Utilisez cet endpoint pour `GET /transactions/&#123;id&#125;` (Obtenir une transaction par ID).


## Authentification

Les routes marchandes nécessitent une clé API dans l’en-tête `X-API-KEY` (voir [Vue d’ensemble](/api)). Utilisez une clé **test** avec `https://sandbox.api.lomi.africa` et une clé **live** avec `https://api.lomi.africa`.

## Endpoint

`GET /transactions/{id}`

URLs de base :

- `https://sandbox.api.lomi.africa`
- `https://api.lomi.africa`

## Requête

### Paramètres de chemin

| Nom | Obligatoire | Schéma | Description |
| --- | --- | --- | --- |
| `id` | Oui | — | UUID de la transaction |

### Paramètres de requête

_Aucun paramètre de requête._




## Réponses

| Statut | Description |
| --- | --- |
| `200` | Détails de la transaction |
| `401` | Clé API invalide ou manquante |
| `404` | Transaction introuvable ou accès refusé |

## Erreurs

Les erreurs suivent le format JSON standard (code de statut et message d'erreur). Validez les entrées avant appel ; **401** indique une clé manquante/invalide, **404** une ressource introuvable pour cette organisation, **429** une limite de requêtes. Pour les retries sûrs sur les créations, envoyez une clé d’idempotence quand votre flux le permet.

## Exemple

```bash
curl -sS -X GET "https://sandbox.api.lomi.africa/transactions/value" \
  -H "X-API-KEY: $LOMI_API_KEY"
```
