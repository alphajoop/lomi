## Overview

Record a usage event

Idempotent usage ingest. Events are processed asynchronously and update meter balances when matched.


### When to use this

Call from your app whenever billable usage occurs; use a stable `transaction_id` per logical event.

### Good to know

Returns `202 Accepted`. Confirm `processing_status` via webhooks or polling `GET /usage-events/&#123;id&#125;`.

## Authentication

Merchant routes require an API key in the `X-API-KEY` header (see [Integration overview](/api)). Use a **test** key against `https://sandbox.api.lomi.africa` and a **live** key against `https://api.lomi.africa`.

## Errors

Errors follow the standard JSON error format (status code and machine-readable message). Validate inputs before calling; **401** indicates a missing/invalid key, **404** a missing resource for this organization, **429** rate limiting. For safe retries on create-style calls, send an idempotency key when your flow supports it.
