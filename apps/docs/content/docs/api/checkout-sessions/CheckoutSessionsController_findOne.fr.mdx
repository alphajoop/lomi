## Aperçu

Obtenir une session de paiement par ID

Renvoie le détail d’une session (statut, client et produits associés).


### Quand l’utiliser

Interrogez ou affichez après redirection checkout, ou lors de notifications asynchrones indexées par ID de session.

### Voir aussi

[Lister les transactions](/api/transactions/TransactionsController_findAll)


## Authentification

Les routes marchandes nécessitent une clé API dans l’en-tête `X-API-KEY` (voir [Vue d’ensemble](/api)). Utilisez une clé **test** avec `https://sandbox.api.lomi.africa` et une clé **live** avec `https://api.lomi.africa`.

## Endpoint

`GET /checkout-sessions/{id}`

URLs de base :

- `https://sandbox.api.lomi.africa`
- `https://api.lomi.africa`

## Requête

### Paramètres d’URL

| Nom | Obligatoire | Schéma | Description |
| --- | --- | --- | --- |
| `id` | Oui | — | UUID de la session |

### Paramètres de requête

_Aucun paramètre de requête._




## Réponses

| Statut | Description |
| --- | --- |
| `200` | Détails de la session |
| `401` | Clé API invalide ou manquante |
| `404` | Session introuvable ou accès refusé |

## Erreurs

Les erreurs suivent un format JSON standard. **401** : clé manquante ou invalide. **404** : ressource introuvable. **429** : trop de requêtes. Pour les créations, envoyez une clé d’idempotence si votre flux le permet.

## Exemple

```bash
curl -sS -X GET "https://sandbox.api.lomi.africa/checkout-sessions/value" \
  -H "X-API-KEY: $LOMI_API_KEY"
```
