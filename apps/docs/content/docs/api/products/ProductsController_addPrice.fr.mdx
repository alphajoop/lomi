## Aperçu

Ajouter un prix à un produit

Ajoute une nouvelle option tarifaire à un produit (palier, devise ou période). Un produit ne peut avoir au plus 3 prix actifs. Les prix existants ne se modifient pas : créez-en un nouveau.


### Quand l’utiliser

Utilisez pour un nouveau marché ou une deuxième option de facturation sur le même produit.

### Voir aussi

[Récupérer un produit](/api/products/ProductsController_findOne)


## Authentification

Les routes marchandes nécessitent une clé API dans l’en-tête `X-API-KEY` (voir [Vue d’ensemble](/api)). Utilisez une clé **test** avec `https://sandbox.api.lomi.africa` et une clé **live** avec `https://api.lomi.africa`.

## Endpoint

`POST /products/{id}/prices`

URLs de base :

- `https://sandbox.api.lomi.africa`
- `https://api.lomi.africa`

## Requête

### Paramètres d’URL

| Nom | Obligatoire | Schéma | Description |
| --- | --- | --- | --- |
| `id` | Oui | - | UUID du produit |

### Paramètres de requête

_Aucun paramètre de requête._


### Corps de la requête

_Pas de corps JSON pour cette opération._


## Réponses

| Statut | Description |
| --- | --- |
| `201` | Prix ajouté avec succès |
| `400` | Entrée invalide ou nombre maximal de prix dépassé |
| `401` | Clé API invalide ou manquante |
| `404` | Produit introuvable ou accès refusé |

## Erreurs

Les erreurs suivent un format JSON standard. **401** : clé manquante ou invalide. **404** : ressource introuvable. **429** : trop de requêtes. Pour les créations, envoyez une clé d’idempotence si votre flux le permet.

## Exemple

```bash
curl -sS -X POST "https://sandbox.api.lomi.africa/products/value/prices" \
  -H "X-API-KEY: $LOMI_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```
