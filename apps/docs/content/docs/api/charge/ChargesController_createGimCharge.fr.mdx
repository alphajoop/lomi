## Aperçu

Create GIM Pay card charge (direct PayByCard)

Charges a card via GIM Pay PayByCard. May return a redirect URL for 3DS or signal retry_other_rail to try another card-payment rail.


### Quand l’utiliser

Utilisez pour la capture carte côté serveur lorsque votre intégration appelle GIM Pay directement plutôt que le checkout hébergé ou Payment Elements.

### À savoir

Traitez PAN/CVV uniquement dans un environnement conforme PCI. Suivez `next_action` pour la 3DS et `retry_other_rail` en cas de refus du rail principal.

### Voir aussi

[Créer un encaissement carte](/api/charge/ChargesController_createCardCharge) · [Encaissements directs](/build/direct-charges)


## Authentification

Les routes marchandes nécessitent une clé API dans l’en-tête `X-API-KEY` (voir [Vue d’ensemble](/api)). Utilisez une clé **test** avec `https://sandbox.api.lomi.africa` et une clé **live** avec `https://api.lomi.africa`.

## Endpoint

`POST /charge/gim`

URLs de base :

- `https://sandbox.api.lomi.africa`
- `https://api.lomi.africa`

## Réponses

| Statut | Description |
| --- | --- |
| `201` | GIM charge created |

## Erreurs

Les erreurs suivent un format JSON standard. **401** : clé manquante ou invalide. **404** : ressource introuvable. **429** : trop de requêtes. Pour les créations, envoyez une clé d’idempotence si votre flux le permet.

## Exemple

```bash
curl -sS -X POST "https://sandbox.api.lomi.africa/charge/gim" \
  -H "X-API-KEY: $LOMI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"amount":10000,"pan":"4221941234569109","expiry":"06/25","cvv":"123"}'
```
